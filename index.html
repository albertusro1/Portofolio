Payments & Loyalty Aug - Nov 2025

Regional Reward System Replatform

Migrating OCBC's siloed loyalty rewards system across 4 countries (SG, MY, HK, ID) to a unified real-time transaction engine.

The Situation (The Challenge)

Bank OCBC operated separate, isolated reward and loyalty systems across its individual regional markets. To unify the user experience and create regional synergies, the bank decided to migrate these siloed platforms into a single, major cross-regional loyalty transaction engine across Singapore, Malaysia, Hong Kong, and Indonesia.

The Task (My Mandate)

Serve as the dedicated System Analyst representing the Indonesian market. I was tasked with translating complex regional commercial requirements into concrete functional specifications (BRDs, FRDs, SRS), modeling system architectures, managing a backlog of over 400 user stories, and resolving OJK data-residency compliance rules.

The Action (My Process & Deliverables)

  • Requirements Engineering: Authored comprehensive BRDs and created UML Sequence Diagrams mapping regional OAuth 2.0 authentication flows and point balances.
  • API Architecture: Designed specifications for 30+ microservice RESTful APIs routed securely through the enterprise gateway.
  • Integration Design: Architected ISO 8583-aligned message switching pathways to connect with Traveloka, iPay88, and KAI booking APIs.
  • Performance Optimization: Engineered an in-memory Redis caching layer and Kafka event topics to buffer point transaction events during high-concurrency periods.

The Result (Quantifiable Outcomes)

70%+ API Latency Cut
20K+ Monthly Redemptions
100% OJK Compliant

Successfully consolidated the regional loyalty architecture, decreasing integration latencies from ~300ms down to 50-100ms and removing 30% database overhead through efficient caching.

Infrastructure & DevOps Jan - May 2025

Active-Active Database HA & Telemetry Migration

Migrating transactional cores from Active-Passive configuration to a high-availability setup and consolidating bank-wide monitoring.

The Situation (The Challenge)

To reduce high licensing overheads, the company decided to migrate its bank-wide database monitoring from costly proprietary enterprise applications to open-source observability solutions. Concurrently, the existing active-passive database configuration was not robust enough; failover swing times and system recovery downtimes were too long under failure scenarios, creating an urgent need to migrate to a highly robust Active-Active database High Availability (HA) replication framework.

The Task (My Mandate)

Analyze requirements and architect a secure migration to a database High Availability (HA) replication framework. Standardize system observability and metric monitoring across 1,000+ servers while transitioning the monitoring core to open-source software without reducing bank telemetry coverage.

The Action (My Process & Deliverables)

  • High Availability Mapping: Authored database failover procedures and modeled data replication flows using BPMN activity diagrams.
  • Telemetry Standardisation: Consolidated metric metrics across 1,000+ servers, mapping virtualised parameters to Prometheus server scraper rules.
  • Dashboard Engineering: Configured centralized Grafana observability dashboards and integrated shift schedule tracking for incident response teams.
  • Migration Elicitation: Managed UAT testing runs and database sync checks before executing master promotion scripts.

The Result (Quantifiable Outcomes)

50%+ Failover Downtime Cut
1,000+ Servers Monitored
100% SLA Coverage

Successfully completed the open-source monitoring migration to Prometheus and Grafana. Cut master DB promotion downtime to just 12 seconds while saving annual enterprise license overheads.
